# 超级管理员操作手册

版本：v1.0 ｜ 视角：超级管理员（Super Admin）｜ 系统：代理管理后台

---

## 1. 前言

### 1.1 本文档给谁看

拥有 **超级管理员（role.admin）** 角色的账号使用者。日常职责聚焦在 **账号 / 角色 / 权限** 三件事上，不参与具体业务处理。

### 1.2 覆盖范围

| 本手册覆盖 | 不覆盖（由业务角色处理） |
|---|---|
| 系统用户的创建、编辑、启用/停用、删除、重置密码 | 代理审核、代理邀请用户管理 |
| 角色的创建、编辑、启用/停用、删除、架构维护 | 意见反馈处理、订单查询等 |
| 角色的菜单权限、按钮权限、数据权限配置 | 财务对账、报表导出 |

---

## 2. 名词与核心概念

| 名词 | 释义 |
|---|---|
| 系统用户 | 能登录后台的账号（如 admin、ops001），一个自然人一个账号 |
| 角色 | 权限的集合（如"运营"、"客服"、"风控"）。一个用户可挂多个角色，取并集 |
| 菜单权限 | 该角色能"看到"哪些菜单（如"代理列表"、"意见反馈"）|
| 按钮权限 | 该角色在菜单页面内能执行哪些操作（如查看/新增/编辑/删除/审核/导出）|
| 数据权限 | 该角色能"看到"哪些数据范围（当前仅支持 **地区维度**）|
| 层级权限（scopeType）| hierarchy = 只可管理"下属角色"及其用户；peer = 平级，见到什么就管什么 |
| 上级角色（parentId）| 用于组织架构表达"部门/上下级"关系，配合"层级权限"生效 |

---

## 3. 权限模型总览

### 3.1 三层关系

```
[系统用户]
   │  绑定 1..N 个
   ▼
[角色] ─────────────┐
   │  配置          │
   ├─ 菜单权限       │
   ├─ 按钮权限       │
   └─ 数据权限       ▼
              [菜单/按钮/数据范围]
```

### 3.2 关键规则

1. **权限取并集**：一个用户挂多个角色，最终权限 = 各角色权限的 **并集**（有一个能看就能看）。
2. **菜单未勾选 → 不显示**：角色未配置的菜单，用户登录后左侧菜单里直接不出现。
3. **按钮未勾选 → 不显示或点击无效**：如仅配了"查看"没配"编辑"，用户能看列表但看不到"编辑"按钮。
4. **数据权限维度**：目前仅"地区"（如 +86、+91 等）。未来可能扩展"部门/项目"维度。
5. **层级权限 vs 平级权限**：
    - **平级（peer，默认）**：只按上面 1~4 条控制。
    - **层级（hierarchy）**：额外叠加一层"只能管下属"限制。适用于"部门主管只能看本部门"的场景。
6. **admin 角色天生 = 全部权限**（menus:*、regions:*），且 **不能被删除/停用/降级**（系统保护）。

## 4. 系统用户管理

菜单入口：**系统管理 → 系统用户**

### 4.1 新增系统用户

**必填项**：用户名、真实姓名、邮箱、手机号、角色（至少 1 个）、状态（默认启用）

**关键规则**：

- **用户名全局唯一**，创建后不可修改（如需变更 → 删除后重建，或联系开发调整）。
- **角色多选**：勾选 1 个或多个角色，权限取并集。
- **不需要设置初始密码**：新用户会通过邮箱收到激活/首次登录链接（或由后台默认策略生成初始密码，具体以实现为准）。
- **状态**：默认"启用"。停用状态下账号无法登录，但记录保留。

### 4.2 编辑用户信息

**可修改**：真实姓名、邮箱、手机号、角色（增减/替换）、状态

**不可修改**：用户名（一经创建终身固定）

**注意**：修改角色后，用户 **下一次点击菜单或刷新页面** 才生效（当前会话内旧权限可能仍缓存）。

### 4.3 重置密码

**入口**：用户行 → "重置密码"按钮

**规则**：

- 会立刻使当前密码失效，向该用户的 **注册邮箱** 发送新密码或密码重置链接。
- 操作前确认邮箱地址正确，否则用户无法收到。
- **超级管理员本人的密码** 不建议在此重置（建议用"忘记密码"自助流程），避免锁死自己。

### 4.4 启用 / 停用

**入口**：用户行 → "启用" / "停用"按钮

**规则**：

- 停用后 **立即生效**，该用户所有正在进行的会话下次请求即会被踢下线。
- 停用不删除数据，可随时恢复。
- **admin 角色的用户不能停用**，按钮会被禁用或提示"不允许操作超级管理员账号"。

### 4.5 删除用户

**入口**：用户行 → "删除"按钮 → 二次确认

**规则**：

- 删除是 **物理删除**（当前实现），操作前请确认。
- **挂着 role.admin 角色的用户不能删除**（系统保护，避免最后一个超管被清空导致无人能登入）。若确需删除超管账号，请 **先移除其 admin 角色**，再删除。
- 员工离职时的推荐做法：**先停用**（保留数据 30~90 天），确认无需数据交接后再删除。

## 5. 角色管理

菜单入口：**系统管理 → 角色管理**

### 5.1 新增角色

**必填项**：角色名称（中）、角色名称（英）

**可选项**：上级角色、层级权限（勾选框）、状态

**关键规则**：

- **角色编码由系统自动生成**（role\_<时间戳>），不需要人工填写、不可修改。
- **描述字段已从表单移除**（如需业务补充说明，可在角色名内表达）。
- **上级角色**：为空表示顶层。选定后进入组织架构。
- **层级权限（scopeType）**：
    - **不勾选** = 平级（peer），此角色 **看到什么就能管什么**，不受上下级限制。
    - **勾选** = 层级（hierarchy），此角色 **只能管理其下属角色及所属用户**。典型场景：部门主管。
- 新增角色 **默认无任何菜单/按钮/数据权限**，需要再进"权限配置"里勾选。

### 5.2 编辑角色

**可修改**：名称（中/英）、状态、上级角色、层级权限

**不可修改**：角色编码、admin 角色的核心属性

**上级角色循环检查**：编辑时下拉里会 **自动排除"自己"和"所有下属"**，防止循环引用（A → B → C → A 这种）。

### 5.3 启用 / 停用角色

**入口**：角色行 → "启用" / "停用"按钮

**规则**：

- 停用后，**挂着此角色的用户会立即失去此角色带来的所有权限**（如果该用户还有其它角色，其它角色权限保留）。
- admin 角色不能停用。

### 5.4 删除角色

**入口**：角色行 → "删除"按钮 → 二次确认

**规则**：

- **admin 角色不能删除**（系统保护）。
- **有子角色的角色不能删除**（组织架构完整性保护）。需先删除或迁移所有下属角色。
- **正在被用户使用的角色**：当前允许直接删除。删除后该用户会失去此角色（若无其它角色，可能无任何权限）。**建议先在"系统用户"里检查引用，把用户的角色改绑到新角色后再删除**。

### 5.5 查看角色架构图

**入口**：角色管理页面右上角"角色架构"按钮

**用途**：可视化查看当前所有角色的父子层级关系，快速验证组织结构是否符合预期。适合在 **大批量角色调整后** 做整体检查。

## 6. 给角色配权限

**入口**：角色行 → "权限配置"按钮 → 打开权限配置弹窗

### 6.1 弹窗结构

权限配置分 **左右两栏 + 底部数据权限**：

```
┌─────────────────────────────────────────────────┐
│ 【左栏】菜单树              │ 【右栏】按钮权限详情 │
│  - 用户管理                │                     │
│    □ 代理邀请用户           │  当前选中：代理列表   │
│    □ 我的代理              │  □ 查看   □ 新增    │
│    ■ 代理列表 (在此)       │  □ 编辑   □ 删除    │
│  - 数据报表                │  □ 审核   □ 导出    │
│    □ 代理业绩报表           │                     │
│  - 系统管理                │                     │
│    □ 系统用户              │                     │
│    □ 角色管理              │                     │
│    □ 菜单管理              │                     │
├─────────────────────────────────────────────────┤
│ 【数据权限 - 地区】                                │
│  □ 全部    □ +86  □ +91  □ +62  □ +66  ...     │
└─────────────────────────────────────────────────┘
```

### 6.2 菜单权限配置

**操作步骤**：

1. 左栏勾选目标菜单前的复选框 → 该菜单对此角色可见。
2. 半勾选状态（部分按钮已配、部分未配）会显示为 "-"。
3. 全部按钮都勾选时，菜单前显示"全选"态。

**关键规则**：

- 未勾选的菜单，用户登录后 **左侧菜单栏不显示** 该项。
- 若模块（如"数据报表"）下所有菜单都未勾选，模块本身也不显示。

### 6.3 按钮权限配置

**操作步骤**：

1. 左栏点击某个菜单（如"代理列表"）→ 右栏出现该菜单的所有按钮列表。
2. 勾选需要开放给该角色的按钮（如"查看"、"编辑"、"审核"）。

**常见按钮类型**：view（查看/进入页面）、add（新增）、edit（编辑）、delete（删除）、audit（审核）、export（导出）、config（高级配置）

**关键规则**：

- **view 是所有其它按钮的前置权限**：只勾"编辑"不勾"查看"，用户连页面都进不了，编辑按钮自然也用不上。**推荐至少勾选 view**。
- 未勾选的按钮，用户看不到（或点击后提示"无权限"）。

### 6.4 数据权限（地区）

**操作步骤**：底部"地区"区域勾选允许的国家/地区区号。

**关键规则**：

- 勾选"全部" = regions:*，此角色可看所有地区数据。
- 勾选具体几个 = regions:['+86', '+91', ...]，只能看这些地区下的用户/代理数据。
- 未勾选任何地区 = 此角色看不到任何业务数据（列表全空）。

### 6.5 保存与生效

- 点击"保存"后配置立即写库。
- 该角色下的用户 **下次刷新页面或点击菜单** 时生效。

### 6.6 快速复制权限（若支持）

若右上角有"从已有角色复制"或"同步权限"按钮：

- 选一个参考角色 → 一键复制其菜单/按钮/数据权限到当前角色。
- 适合"新建一个和运营类似但少两个权限"这种场景，快过手动逐个勾选。

## 7. 附录：字段说明速查表

### 7.1 系统用户字段

| 字段 | 类型 | 是否必填 | 是否可改 | 说明 |
|---|---|---|---|---|
| 用户名 (username) | 字符串 | 是 | 否 | 全局唯一，创建后不可改 |
| 真实姓名 (realname) | 字符串 | 是 | 是 | 用于内部识别 |
| 邮箱 (email) | 字符串 | 是 | 是 | 用于密码重置/通知 |
| 手机号 (phone) | 字符串 | 是 | 是 | 用于验证 |
| 角色 (roleKeys) | 数组 | 是 | 是 | 可多选，权限取并集 |
| 状态 (status) | 枚举 | 是 | 是 | 1=启用 / 0=停用 |
| 上次登录时间 (lastLogin) | 时间戳 | 否 | 自动 | 用户每次登录自动更新 |

### 7.2 角色字段

| 字段 | 类型 | 是否必填 | 是否可改 | 说明 |
|---|---|---|---|---|
| 角色编码 (code) | 字符串 | 否 | 否 | 系统自动生成 |
| 角色名称（中） (nameZh) | 字符串 | 是 | 是 |  |
| 角色名称（英） (nameEn) | 字符串 | 是 | 是 |  |
| 上级角色 (parentId) | 数字 | 否 | 是 | 为空 = 顶层；不能选自己或下属 |
| 层级权限 (scopeType) | 枚举 | 否 | 是 | hierarchy / peer（默认） |
| 状态 (status) | 枚举 | 是 | 是 | 1=启用 / 0=停用 |
| 创建时间 (createdAt) | 日期 | 否 | 自动 |  |
| 用户数 (userCount) | 数字 | 否 | 自动 | 挂此角色的用户数量 |

### 7.3 权限配置字段

| 字段 | 结构 | 说明 |
|---|---|---|
| 菜单权限 (menus) | '*' 或 { 'menu.action': 1, ... } | '*' = 全部；对象 = 具体勾选项 |
| 数据权限-地区 (regions) | '*' 或 ['+86', '+91', ...] | '*' = 全部地区 |
